# Phase 3 Decisions

## D1 — One implicit entry Skill per specialized factory
**Decision:** expose six factory skills, not one skill for every subtask.

**Reason:** Codex uses Skill metadata for discovery and gives the initial Skill list a bounded context budget. Fine-grained procedures therefore live in `references/` and are loaded only after the factory is selected.

## D2 — General Factory is not implicit
**Decision:** `factory-general` sets `allow_implicit_invocation: false`.

**Reason:** a broad fallback description can shadow more precise software/CAD/research/data/document skills. The later global router selects General explicitly when no specialized domain fits.

## D3 — Existing tooling is inherited
**Decision:** Factory Skills do not declare hard dependencies on specific MCP servers.

**Reason:** the user's software environment already contains miscellaneous MCPs/Skills and the CAD MCP is still being built. The factory should discover/reuse available tools without overwriting or duplicating them.

## D4 — Domain knowledge belongs in Skills; model choice belongs in Router/Agents
**Decision:** Skills define workflow, evidence standards, handoffs, and specialized engineering/software practice. They do not independently choose arbitrary model IDs.

**Reason:** keeping model policy in Phase 1/2 prevents conflicting cost rules and makes routing testable.

## D5 — CAD reasoning and CAD execution stay separated
**Decision:** mechanism/engineering reasoning, CAD recipe planning, CAD execution, DFMA, and verification are distinct responsibilities.

**Reason:** exact geometry should be measured/generated by CAD tools; LLM qualitative confidence is not a substitute for BRep/dimension/interference checks.
