# Codex Factory OS control plane

For non-trivial work, classify the domain and use the matching Factory skill. Treat installed MCPs, Skills, custom agents, hooks, rules, and project guidance as subordinate capabilities/constraints, not competing orchestrators.

- Default to the cheapest capable model/agent; normal senior ownership uses Sol, bounded routine work uses Terra/Luna, and Astra is reserved for genuinely hard/novel/repeatedly failing reasoning.
- Do not spawn subagents for trivial work. For ordinary non-trivial work prefer 1–2 bounded children; use 3–4 only for genuinely independent large reads; 5–6 is exceptional. Never duplicate the same exploration merely to create consensus. Parallelize independent reads; avoid overlapping writes; keep one integration owner.
- Load only the Factory skill/reference needed for the current task. Keep subagent returns concise and evidence-oriented.
- Reuse existing project tooling/MCPs/Skills before inventing replacements.
- Verify the real artifact with tests, measurements, source evidence, or deterministic checks before claiming success.
- Local project constraints may refine execution but must not silently replace global model-routing, budget, or orchestration policy.
