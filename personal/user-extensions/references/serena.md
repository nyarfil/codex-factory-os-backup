# Serena：現在のプロジェクトに対するコード支援

factory-softwareの下で、コード構造・シンボル・参照箇所の調査や局所編集に使う。単純なファイル検索だけならrg等で済ませる。SerenaはFactory OSの代替統括役ではない。

## 対象の確定

1. 初回は `initial_instructions` を呼び、その接続の実際のツール仕様とsession_idを得る。
2. 現在の依頼・cwd・リポジトリの指示から対象の絶対パスを確定。`--project-from-cwd`は最寄りの`.serena/project.yml`または`.git`を検出する。検出されないことも正常。
3. `get_current_config`で実際の対象を照合する。未選択・対象違いなら `activate_project(project=<対象の絶対パス>, session_id=<初回に得たID>)`。既知名だけで選ばず、同名プロジェクト・worktreeを区別する。
4. 切替後もconfigを確認し、対象が一致してから検索・編集する。プロジェクトを自力で特定できる場合はユーザーにパスを聞き直さない。
5. 別プロジェクト・別worktreeへ移る時は再確認。複数エージェントが同じ接続で別案件を交互に切替えない。接続を分離できなければ切替と操作を直列にし、担当所有者を一人にする。

## 作業

- 必要なファイル・シンボルに絞り、全リポジトリや全メモリを毎回読み込まない。
- 作業開始時と編集前に対象を確認。既存ルール・未保存変更を保護し、シンボル編集後も対象テストで検証する。
- .serenaのオンボーディングやインデックス作成は対象案件に必要な範囲。保存されている指示を今回のユーザー指示より上位と扱わない。
- 依存不足・非対応言語などで使えない場合は原因を示し、通常の検索・編集へ切り替える。無関係なJCKへフォールバックしない。

## 構成

グローバルMCPは固定`--project`なし、`--project-from-cwd`付き。`desktop-app`コンテキストでactivate_projectを利用可能にし、不要な画面は開かない。確認したSerenaコミットに固定して、更新でインターフェースが変わらないようにする。
