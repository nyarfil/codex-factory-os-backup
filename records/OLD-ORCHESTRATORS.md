# 旧統括役とは何か

「旧」はFactory OS導入前の構成を指す。

## mechanical-cad-orchestrator

以前あなた専用に入っていた、CAD作業の進め方を決めるスキル。バックアップに実体がある。

- 物理部品の依頼を検知し、CAD担当として暗黙に起動する。
- 通常はText-to-CADのPythonを正本と宣言し、F3D・Fusion指定等ではFusion正本に切り替える。
- cad、cad-viewer、step-parts、dfam-check、Fusionのうち何を使うか選ぶ。
- 要件整理、生成、寸法・干渉・組立・造形性検証、NG修正、完成判断まで進行する。

Factory OSのfactory-cad-3dpもCADの担当選択・設計・検証・統合を担うため、両方を常時起動すると、担当とツール選択が二重になる。特に旧スキルの「通常Text-to-CAD正本」という既定と、Factory側の「既存の正本・指定ツールを維持する」方針を一貫して扱う必要がある。

現在はFactory OSがモデル・担当・委譲・予算を管理し、factory-cad-3dpがCAD作業を統括する。Fusion、Text-to-CAD、ForgeCAD、造形性チェック等はその下の専門機能として使う。単一正本、元データ保護、寸法・干渉の実測、未検証を合格にしない方針はFactoryと個人拡張に引き継いでいる。

## company-director

導入前バックアップでは空フォルダーだけで、SKILL.mdがなかった。名前から推測して詳細な役割や実動作を断定することはできない。今回は復元できる実体がないため対象外。実体を確認したCAD統括スキルと同列に説明した以前の表現は大まかすぎた。

## 現在の役割分担

| 層 | 担当 |
|---|---|
| Factory OS | 仕事の分類、モデル・委譲・予算、全体の進め方 |
| 各Factory | ソフト、CAD、データ、文書などの専門的な作業と検証 |
| 個人拡張カタログ | 使える専門機能と資料の索引 |
| MCP・CLI・専門資料 | 実際のコード検索、形状生成、画面操作、ファイル出力 |

参照資料を追加しても新しい統括役は増えない。必要な案件でだけ読み、Factory側の判断に従って利用する。
